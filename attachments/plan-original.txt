# 开工方案（实现前原稿）

记录时间：2026-11-09 14:48（北京时间）。输入：附件 VC-FIN-001 / V3.0 与原始 JSON。此文件在应用源码编写前创建，交付时保留，不根据结果回填。建议预算 3–4 小时；实际用时另记于 DESIGN.md。

## 理解与完成标准

这是固定快照下的交易前分析工具，核心闭环是「查看原组合 → 发现集中度超限 → 顺序添加交易 → 比较 → 命名保存 → 刷新/重启后查看」。后端必须承担计算、校验、保存；只做静态页面或浏览器本地存储不满足要求。以附件 AC-01～AC-05 的具体数值作为验收依据。

## 范围与假设

- 必做：总资产、现金、六项持仓、行业分布、快照时间；标的 >30% / 行业 >50% 提醒；顺序模拟；失败不变更结果；方案列表和只读详情；本地持久化。
- 不做：登录、多组合、多币种、实时行情、费用/税/收益预测、真实交易、已保存方案编辑删除、云部署。
- 已明确：数量为正整数且不要求整手；现金进入总资产、不归行业；等于阈值不超限；卖出所得可供后续买入。
- 自行确定：空交易可预览但不能保存；清空未保存模拟需确认；方案允许同名，以 ID 区分；保存时绑定原始快照与计算版本，历史结果不随当前数据变更。

## 技术与数据取舍

Python 3.11 + FastAPI 提供 JSON API 和同源静态页面，SQLite 保存方案；前端使用原生 ES modules / CSS，免前端构建。现有环境具备这些依赖，优先减少评审启动步骤。金额使用整数分（从 Decimal 精确导入），占比阈值用交叉乘法比较，展示两位小数不参与判定。每次模拟在原始数据副本上重放完整操作列表，整体失败则丢弃，后端不保存临时模拟状态。保存快照和操作，重开用指定计算版本重算。

## 实施与 AI 协作

1. 先保存本方案和附件校验信息；记录关键约定。
2. AI 实现纯计算模块、接口和 SQLite，再实现概览、模拟、方案三页。
3. 用附件的手算常量作为独立断言，检查 AI 对阈值、顺序、失败原子性、持久化的实现；修正后再测。
4. 用真实浏览器完成核心闭环，保存截图和实际结果；最后完成设计、运行说明、验证记录与复盘。不将 AI 自检描述为候选人已人工审查。

## 验证计划

必验 AC-01～AC-05，追加小数/布尔/字符串数量、未知代码、舍入后看似等于阈值、先卖后买与反序、全现金、重复保存、失效快照、错误请求、文件隔离。实际关闭并重启服务后重开 AC-03 方案，核对原始组合不变。浏览器检查桌面/手机布局、错误提示、保存重开与控制台；失败修复过程和未验证项如实记录。
